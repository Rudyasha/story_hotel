# Чек-листы по монетизации

<div class="suite-summary" markdown>

**24 проверки · 6 подразделов · UI / Client и Backend / API**

Фокус: корректная цена, однократное начисление, целостность баланса и безопасное восстановление операций.

</div>

Незаполненные чекбоксы означают **«не выполнено»**. Для прогона фиксировать сборку, платформу, регион магазина, тестовый аккаунт и результат `Passed / Failed / Blocked`. Неопределённые продуктовые ожидания сначала согласовать по связанным вопросам; они не являются установленными требованиями.

## 1. Витрина и отображение покупки

- [ ] **MON-01 · P1 · UI** — Название, состав, количество, цена и валюта каждого товара совпадают с актуальным каталогом для платформы и региона игрока; скидки и бонусы не искажают итоговую стоимость.
- [ ] **MON-02 · P0 · UI / интеграция** — Товар, сумма и валюта в системном платёжном окне соответствуют выбранному предложению. При изменении цены игрок видит актуальные условия до подтверждения оплаты.
- [ ] **MON-03 · P1 · UI** — Бонус первой покупки ×2 показывается только для доступного предложения и обновляется после использования, повторного входа и синхронизации аккаунта.
- [ ] **MON-04 · P1 · Client / API** — Таймер бесконечных жизней соответствует времени действия награды: уход в фон, перезапуск и смена локальных часов не сбрасывают и не продлевают его; после истечения эффект прекращается.

## 2. Платёж и начисление товара

- [ ] **MON-05 · P0 · Backend / API** — Начисление происходит после доверенной проверки оплаты и её привязки к игроку и товару. Подмена цены, количества, получателя или неподтверждённого клиентского статуса не даёт товар.
- [ ] **MON-06 · P0 · E2E** — После подтверждённой покупки выданы все компоненты набора в нужном количестве; баланс кристаллов, монет, ключей и бустеров в UI соответствует серверному состоянию.
- [ ] **MON-07 · P0 · Backend / API** — Повторные, параллельные и отложенные уведомления об одной транзакции не создают повторное начисление; одна и та же покупка не может быть зачислена другому аккаунту.
- [ ] **MON-08 · P0 · Backend / API** — Бонус первой покупки выдаётся однократно по согласованной области действия бонуса, включая две одновременные покупки; базовый товар по каждой успешной транзакции начисляется полностью.
- [ ] **MON-09 · P0 · E2E** — При потере связи или закрытии игры после оплаты незавершённая выдача восстанавливается по подтверждённой транзакции. Игрок получает оплаченный товар один раз, без повторной оплаты.

## 3. Обмен внутриигровой валюты

- [ ] **MON-10 · P1 · UI / API** — Для стоимости `C` проверить баланс `C − 1`, `C`, `C + 1`: при нехватке обмен не выполняется; при достаточном балансе списывается ровно `C` и выдаётся согласованное количество монет.
- [ ] **MON-11 · P0 · Backend / API** — Списание кристаллов и выдача монет выполняются целиком либо не выполняются. Сбой между этапами не оставляет частичный результат; курс и количество проверяются сервером.
- [ ] **MON-12 · P0 · Backend / API** — При балансе на один обмен повтор одного запроса и два независимых параллельных запроса не приводят к лишнему обмену, двойному списанию или отрицательному балансу.

## 4. Ключи и предложение «Открыть все»

Для проверок ниже используется рабочее допущение **1 ключ = 1 открытие**. Его нужно подтвердить вместе с моделью поля: [Q04–Q05](analyst-questions.md#q04).

- [ ] **MON-13 · P1 · UI** — Проверить баланс `N − 1`, `N`, `N + 1`, где `N` — число доступных неоткрытых чемоданов. Предложение покупки появляется только при нехватке; при `N = 0` нет платной операции. [Q14](analyst-questions.md#q14)
- [ ] **MON-14 · P1 · UI / API** — Стоимость рассчитана только для оставшихся доступных чемоданов; ранее открытые объекты и их награды не входят в текущую операцию.
- [ ] **MON-15 · P1 · UI / интеграция** — При нехватке предлагается доступный лот по согласованному правилу «наименьшего», достаточный для покрытия дефицита. Если подходящего лота нет, недоступную покупку нельзя подтвердить. [Q06](analyst-questions.md#q06), [Q16](analyst-questions.md#q16)
- [ ] **MON-16 · P1 · UI / API** — При изменении баланса или поля после открытия попапа предложение актуализируется по согласованному UX; перед выполнением сервер повторно проверяет баланс, доступность ивента и состояние чемоданов. Устаревшие данные не приводят к лишнему списанию. [Q23](analyst-questions.md#q23)

## 5. Списание ключей и выдача наград

- [ ] **MON-17 · P0 · Backend / API** — Списание ключей, открытие выбранных чемоданов и начисление их наград дают согласованный итог без частично сохранённого результата. При нехватке ключей нет списания и выдачи. Остаток ключей сохраняется. [Q18](analyst-questions.md#q18)
- [ ] **MON-18 · P0 · Client / API** — Быстрые повторные нажатия блокируются во время операции; повтор запроса с тем же идентификатором не списывает ключи и не выдаёт награды снова, в том числе после обновления поля.
- [ ] **MON-19 · P0 · Backend / API** — Одновременное ручное открытие, «Открыть все» и действия со второго устройства не открывают один чемодан дважды. Списания соответствуют реально открытым объектам; баланс не уходит в минус. [Q19](analyst-questions.md#q19)
- [ ] **MON-20 · P0 · E2E** — Состав и количество наград в итоговом попапе совпадают с результатом именно этой операции и фактическими начислениями. Учтены все открытые чемоданы, отсутствуют пропуски и дубли. [Q20](analyst-questions.md#q20)

## 6. Сбои, восстановление и завершение сценария

- [ ] **MON-21 · P0 · E2E** — Успешная покупка ключей запускает автоматическое открытие по согласованному сценарию. Если открытие не выполнилось, начисленные ключи не теряются; повтор восстанавливает операцию без повторной оплаты или лишнего списания. [Q15](analyst-questions.md#q15), [Q17](analyst-questions.md#q17)
- [ ] **MON-22 · P1 · UI / интеграция** — Отмена, подтверждённый отказ, ожидающий подтверждения платёж и недоступность магазина различаются в UI. Без подтверждённой оплаты нет начисления и автоматического открытия; отложенный успех обрабатывается один раз. [Q16](analyst-questions.md#q16), [Q22](analyst-questions.md#q22)
- [ ] **MON-23 · P0 · E2E** — После timeout, потери сети или закрытия клиента на любом этапе восстанавливается фактический результат операции. Успешное серверное открытие не выполняется повторно; неизвестный результат сначала сверяется с сервером. [Q17](analyst-questions.md#q17), [Q22](analyst-questions.md#q22)
- [ ] **MON-24 · P2 · UI** — Открытие, показ наград, исчезновение чемоданов и заполнение поля соответствуют утверждённым макетам. Закрытие попапа допустимыми способами и прерывание анимации не мешают продолжить игру и не меняют начисления. [Q07–Q09](analyst-questions.md#q07), [Q21](analyst-questions.md#q21)

## Условия начала прогона

Нужны тестовая сборка, sandbox-платежи, управляемые данные игрока и способ сверки операций с сервером. Для ошибок и повторов — возможность задержать ответ, прервать связь и повторить запрос. Реальные платежи не требуются.

Правила получения ключей через БП, переноса остатка, лимитов и наград после окончания ивента уточняются в [Q03](analyst-questions.md#q03), [Q10–Q13](analyst-questions.md#q10). После согласования они дополнят регрессионный набор.

## Критерий завершения проверки

Все применимые P0 выполнены, экономические операции сверены с сервером, блокирующие вопросы закрыты. Для `Failed` есть баг-репорт, для `Blocked` — конкретная причина. Невыполненные P1/P2 и остаточные риски явно зафиксированы перед решением о релизе.
