## Шаблон баг-репорта

<div class="test-case bug-report" markdown>

### BUG-XXX · [Действие] приводит к [фактический результат] при [условие]

| Поле | Что указать |
| --- | --- |
| Статус | New / In progress / Fixed / Retest / Closed / Reopened |
| Критичность | Blocker / Critical / Major / Minor / Trivial - по фактическому влиянию |
| Приоритет | P0 / P1 / P2 - по срочности исправления |
| Окружение | Версия и build игры, устройство, ОС, backend-стенд, регион магазина, локаль, тип сети |
| Воспроизводимость | Число воспроизведений / число попыток, например 3/3 |
| Связи | ID тест-кейса или название подраздела чек-листа; ссылка на утверждённое требование |

### Предусловия

Указать состояние игрока, ивент и поле, баланс до операции, количество неоткрытых чемоданов, доступный лот и состояние бонусов. Для платежей - sandbox и ожидаемый сценарий провайдера.

### Шаги воспроизведения

1. Подготовить описанное исходное состояние.
2. Выполнить конкретное действие с точными тестовыми данными.
3. Указать момент наблюдаемого отклонения и способ проверки.

<div class="result-panel actual" markdown>

### Фактический результат

Зафиксировать наблюдаемые данные: сообщение на экране, баланс до/после, состояние чемоданов, состав наград и статус операции. Отделить наблюдение от предположения о причине.

</div>

<div class="result-panel expected" markdown>

### Ожидаемый результат

Описать проверяемое поведение и дать ссылку на согласованное правило. Если требование неоднозначно, связать отчёт с [вопросом к аналитику](analyst-questions.md) и отметить, что ожидание требует подтверждения.

</div>

### Влияние и доказательства

- Описать последствия для игрока: потеря покупки, неверный баланс, блокировка сценария или визуальная ошибка; указать доступный обходной путь.
- Приложить скриншот или видео и время воспроизведения с часовым поясом.
- Для экономической операции приложить обезличенные ID операции/транзакции, ответ API и выдержку из журнала начислений с состоянием до и после.
- Перед публикацией удалить токены, платёжные реквизиты и персональные данные из вложений.

### Ретест

Указать исправленную сборку, повторённые шаги, результат и проверку соседних сценариев. Для ошибок повторов дополнительно сверить отсутствие повторного списания и начисления.

</div>

## Готовность отчёта к передаче

- [ ] Название отражает действие, отклонение и существенное условие.
- [ ] Есть воспроизводимые шаги, исходные данные и окружение.
- [ ] Фактический и ожидаемый результаты разделены и подтверждены материалами.
- [ ] Ожидание связано с требованием; неясность отмечена явно.
- [ ] Критичность обоснована влиянием на игрока, приоритет - срочностью исправления.
